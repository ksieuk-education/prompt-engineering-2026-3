# Источники фонограмм

Для опыта использованы три звуковых файла из раздела Apollo and Mercury в коллекции NASA Historical Sounds. Это короткие опубликованные монтажи радиосвязи. Короткая и расширенная версии относятся к сообщению о посадке. Для отрицательного контроля взята другая реплика той же миссии. [Каталог NASA](https://www.nasa.gov/historical-sounds/) · [Условия образовательного использования](https://www.nasa.gov/nasa-brand-center/images-and-media/)

| `eagle-extended.wav` | [Eagle Has Landed Extended](https://www.nasa.gov/wp-content/uploads/2015/01/590333main_ringtone_eagleHasLanded_extended.mp3) | `e1c47957a46fced583e9d8b61a0c377f8ad46300137b0bfb59f9f3a95c836c51` |
| `small-step.wav` | [That's One Small Step for (a) Man](https://www.nasa.gov/wp-content/uploads/2015/01/590331main_ringtone_smallStep.mp3) | `324691d7b1891959672567b0e6e7d43b659ba7af5e09e7883a473a27448380ac` |

Исходные MP3 декодированы FFmpeg в монофонический WAV PCM 16 бит, 8 кГц. Начало и конец фонограмм сохранены. Все позиции в отчете отсчитываются от начала этих файлов. Коэффициенты и кандидаты на совпадение получены программой лабораторной.

Файл `calibration.wav` создан для контрольного опыта из `eagle-short.wav`. В генераторе заданы скорость ×1,017, начальный отступ 0,57 с, коэффициент амплитуды −0,72 и воспроизводимый белый шум. Это учебная производная короткой записи. Для пересборки выполните `poetry run python -m tools.evaluate_speed --write-copy /tmp/calibration.wav`. SHA-256 файла в проекте — `ad6e9c3bcddc56153e83426c0c72845b40dd37eb3274de25718d302178f27f7e`. [Генератор и измерения](../../tools/evaluate_speed.py)

## Текст стенограммы

Для проверки двух расходящихся чтений из PDF NASA извлечены печатные страницы 234 и 320, физические листы 236 и 322. У строки Олдрина на странице 234 в HTML стоит `05 06 46 31`, на изображении — `03 06 46 31`. У слов Коллинза о ретрансляции на странице 320 это `02 06 58 12` и `04 06 58 12`. Цифры сверены по видимому изображению. В текстовом слое самого PDF они тоже распознаны как 05 и 02. SHA-256 двухстраничной выборки — `5edc91b3e51dbf9ed0344ab5ea4f111ae059fed8bec4b0e317205f16e3bfa5c3`. [Два скана](nasa-clock-variants.pdf) · [Метки с номерами строк](transcript-clock-editions.json) · [Оригинальный PDF NASA](https://www.nasa.gov/wp-content/uploads/2026/01/as11-tec.pdf#page=236)

В файл `nasa-page-253.pdf` вынесена физическая страница 255 полного PDF NASA, катушка 54/3. На скане вокруг метки `02 11 26 41` видны `03 11 26 40` и `03 11 26 44`. Эта последовательность подтверждается и печатным листом, и HTML. В архиве сохранены все три значения. SHA-256 отдельной страницы — `d46d78cfa93ec2b6b7b57418832d7f3334ccb47d2d5d6e2dd3ef2f580b862aab`. [Лист из репозитория](nasa-page-253.pdf) · [Скан NASA, стр. 253](https://www.nasa.gov/wp-content/uploads/2026/01/as11-tec.pdf#page=255)

Для поиска взята техническая стенограмма переговоров Apollo 11 за июль 1969 года, опубликованная NASA в OCR HTML. Распознавание подготовил Томас Швагмайер. NASA указывает, что исходные стенограммы были предоставлены прессе в ходе миссии и что для них авторские права не заявлены. Печатная нумерация в выбранной версии идет от 1 до 624. [Описание редакций](https://www.nasa.gov/wp-content/uploads/static/history/alsj/a11/a11trans.html) · [Исходный OCR HTML](https://www.nasa.gov/wp-content/uploads/static/history/alsj/a11/a11transcript_tec.html)

Для страницы 491 использована отдельная копия, переданная Колином Фрайзом из NASA HQ History в Apollo Lunar Surface Journal. В HTML на этом месте стоит помета о поврежденном файле. В полном PDF на физической странице 493 читается только верхняя часть печатного листа. В отдельном скане видна последняя строка с меткой 05 10 10 12. С нее и остальных строк вручную сверили наборный текст. В файл `transcript-491.json` внесены продолжение предыдущей реплики и 17 реплик с собственными метками. Переносы слов внутри печатной строки соединены, рукописные отметки видны на скане. SHA-256 отдельного PDF — `a0fea350824dfde386dbda6c0da35f20edc4aba2c658d06b8487deaae64d5a65`. [Страница журнала](https://apollojournals.org/alsj/a11/a11trans.html) · [Полный скан отдельного листа](https://apollojournals.org/alsj/a11/a11TEC84-2p491.pdf) · [Основное PDF-издание NASA](https://www.nasa.gov/wp-content/uploads/2026/01/as11-tec.pdf)

SHA-256 скачанного HTML — `daf141a2c9030b0ca1e8748962af7a4cbfe227ed324f5c5ca085f063db271b3a`. В файл `transcript-pages.json.gz` попали пронумерованные страницы, с абзацами и исходными обозначениями говорящих. Для пересборки из скачанного файла выполните из корня проекта `poetry run python -m tools.import_transcript a11transcript_tec.html data/field/transcript-pages.json.gz`. В поисковом индексе представлены фрагменты с четырехкомпонентной временной меткой и текстом. Вступление, служебные пометы внутри страниц и продолжения без новой метки можно сверять в полном OCR. В интерфейсе дни и часы исходной метки пересчитаны в суммарные часы миссии.

Файл `transcript-vectors.npz` содержит по одному вектору на размеченную реплику. Их рассчитала локальная EmbeddingGemma 300M. Вход документа включает имя говорящего, если оно известно, и английский текст. Вход запроса использует рекомендованную для поиска инструкцию модели. Векторы сохранены в int8. Поиск нормирует их и сравнивает при 256 и 768 компонентах. Внутри файла сохранены контрольные суммы корпуса и модели из API Ollama. Пересборка выполняется командой `poetry run python -m tools.build_transcript_index` после `ollama pull embeddinggemma:300m`. [Карточка модели Google](https://huggingface.co/google/embeddinggemma-300m) · [Сборка индекса](../../tools/build_transcript_index.py)
